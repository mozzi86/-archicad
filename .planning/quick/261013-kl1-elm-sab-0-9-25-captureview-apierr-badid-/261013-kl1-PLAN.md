## Entwurfsentscheidungen des Planers (Claude's Discretion)

1. **Struktur in CaptureViewCommand.hpp** (header-only bleibt, kein CMake-Eingriff):
   - private `static void GetPrimaryColorDepth (API_ColorDepthID& depth, GS::UniString& name)` mit
     `#if defined (macintosh)` → `APIColorDepth_MiC`/"MiC", `#elif defined (WINDOWS)` → `APIColorDepth_TC24`/"TC24", `#else` → `APIColorDepth_256C`/"256C".
   - private `static GSErrCode TrySave (IO::Location& file, API_ColorDepthID depth, bool view2D, bool crop)` baut fsp UND pict je Versuch frisch:
     `API_FileSavePars fsp = {};`, `fsp.fileTypeID = APIFType_PNGFile;`, `fsp.file = &file;`, `API_SavePars_Picture pict = {};`, `pict.colorDepth = depth;`,
     `pict.dithered = false;`, `pict.view2D = view2D;`, `pict.crop = crop;`, dann `return ACAPI_ProjectOperation_Save (&fsp, &pict);`.
     `keepSelectionHighlight` NICHT erwähnen (bleibt false über `{}`). Das ist der EINZIGE `ACAPI_ProjectOperation_Save`-Aufruf in der Datei.
2. **Rückfall:** Er wird nur versucht, wenn der erste Code `APIERR_BADID` ist UND die Primärtiefe nicht schon `APIColorDepth_256C` ist (im `#else`-Zweig gibt es keine identische
   Wiederholung). Der Rückfall nutzt `APIColorDepth_256C`/"256C". Danach gibt es keinen dritten Versuch.
3. **Namen der Tiefen** sind GS::UniString („MiC“, „TC24“, „256C“). Meldungen laufen über `GS::UniString::Printf` mit `%T` + `.ToPrintf ()` und `%d` + `(int)`, wie im Bestand.
   Ein Versuchsprotokoll `attempts` = „Farbtiefe <Name>: Fehler <Code>“ bekommt bei Rückfall „, Rueckfall 256C: Fehler <Code>“ angehängt (per `+=`/Append).
4. **error.code** = Code des LETZTEN Versuchs. Der Text nennt alle Versuche. Texte (ASCII):
   - Layout/MasterLayout: „CaptureView: Layout-Fenster ('%T'): PNG-Export per API nicht moeglich (%T) - Zeichnung/Grundriss oeffnen oder Layout als PDF publizieren“ (Fenstertyp, attempts)
   - sonst: „CaptureView: Fensterinhalt (Fenstertyp '%T') nicht als PNG speicherbar (%T) - Fenstertyp exportierbar? Pfad beschreibbar?“ (Fenstertyp, attempts)
   - Rücklese: „CaptureView: Save meldete Erfolg (Fenstertyp '%T', Farbtiefe %T), aber die PNG-Datei existiert nicht (Ruecklese)“ (Fenstertyp, benutzte Tiefe)
5. **Schema:** Nach `view2D` kommt ein neues Property `"colorDepth": {"type": "string", "description": "Tatsaechlich benutzte Farbtiefe des PNG-Exports: MiC = macOS, TC24 = Windows, 256C = Rueckfall bei APIERR_BADID, ab 0.9.25."}`.
   **Falle Raw-String:** Im Schematext darf nirgends die Zeichenfolge `)"` stehen, sonst endet der C++-Raw-String `R"(…)"` vorzeitig (Compile-Fehler). Deshalb hat die Beschreibung keine Klammern.
   `required` bleibt [imagePath, view2D], `additionalProperties:false` und die ELMResponseSchemaWithError-Hülle bleiben. Den Kommentar über dem return anpassen
   („Erfolgszweig: 0.9.25 + optionales colorDepth; …“).
6. **Registrierungssatz** (ASCII, führendes Leerzeichen, vor dem schließenden `"` von Z. 1011 anhängen):
   ` 0.9.25: PNG-Export mit Echtfarbtiefe (Mac MiC, Win TC24) statt FromSourceImage gegen APIERR_BADID, bei BADID ein Rueckfall auf 256C; die Antwort meldet die benutzte Tiefe in colorDepth.`
7. **Bekannte Schwäche, bewusst nicht geändert** (eine Ursache pro Version): Die Rücklese prüft nur die Existenz. Eine Altdatei am Zielpfad täuscht Erfolg vor. → Der Testplan
   verlangt je Probe einen neuen Dateinamen. Das wird nur dokumentiert, nicht codiert.
8. **Doku-Ergänzungen ohne Löschung:** Der 0.9.23-Punkt Z. 1580 bekommt den Verweis am ZEILENENDE angehängt (Originalzeile bleibt Präfix). Der 0.9.12/0.9.13-Bullet
   bekommt eine eingefügte Fortsetzungszeile (reine Einfügung). README: ein eingefügter Absatz.
