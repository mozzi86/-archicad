## 1. Zweck

`Create2DElements` ist das Schreib-Gegenstück zu `Get2DGeometryOfElements`. Was der Lesebefehl
liefert, kann man diesem Befehl ohne Umbau zurückgeben. Tapir kann davon nur Polylinien
(`CreatePolylines`); Linien, Bögen, Kreise, Splines und Schraffuren fehlen ganz.

Erster Einsatz: farbige Füllflächen im Flucht- und Rettungswegeplan WiSchu
(Umrisse = Polylinien auf `Z_FR_Rettungswege`, GUID-Register
`~/.scratch/wischu-freising/data/fr/2026-10-13_guid_register.json`).

## 2. Umfang v1

| Typ | `elementType` | Pflichtfelder | Optionale Felder |
|---|---|---|---|
| Linie | `Line` | `begCoordinate`, `endCoordinate` | — |
| Bogen | `Arc` | `origin`, `radius`, `begAngle`, `endAngle` | `ratio` (Ellipse, Standard 1), `angle` (Drehung der Hauptachse, Standard 0), `reflected` |
| Kreis | `Circle` | `origin`, `radius` | `ratio`, `angle` |
| Polylinie | `PolyLine` | `coordinates[]` (≥2) | `arcs[]`, `closed` (Standard false) |
| Spline | `Spline` | `coordinates[]` (≥2) | `closed` (Standard false), `bezierDirs[]` (sonst `autoSmooth`) |
| Schraffur | `Hatch` | `coordinates[]` (≥3) | `arcs[]` und Füllungsfelder (Abschnitt 3.3) |

Nicht in v1: Löcher in Schraffuren, Baustoff-Schraffuren (`API_BuildingMaterialHatch`),
Pfeilspitzen an Linien/Splines, Arbeitsblätter/Details/andere Datenbanken
(nur aktive Grundriss-Datenbank wie `CreateLabels`), Text/Etikett/Bemaßung (gibt es schon).

## 3. Eingabe

```json
{
  "elements": [
    { "elementType": "Hatch",
      "floorInd": 0, "layerName": "Z_FR_Rettungswege",
      "coordinates": [{"x":0,"y":0},{"x":1,"y":0},{"x":1,"y":1},{"x":0,"y":1}],
      "fillName": "Vollfüllung",
      "foregroundRGB": {"red":0.0,"green":0.6,"blue":0.2},
      "backgroundPen": 0, "contourPen": 0 }
  ]
}
```

### 3.1 Gemeinsame Felder (alle Typen)

- `elementType` — Pflicht, eine der sechs Typbezeichnungen (Schreibweise wie Lesebefehl).
- `floorInd` — Geschossindex. Fehlt er, gilt der Wert aus `ACAPI_Element_GetDefaults` (aktuelles Geschoss); die Antwort meldet das tatsächliche Geschoss immer zurück.
- Ebene: `layerName` ODER `layerIndex`; beide fehlen → Werkzeug-Standard. Name hat Vorrang und wird per `ACAPI_Attribute_Search` aufgelöst (Muster `SetLayerCommand.cpp`).
- `pen` — Linienstift (Line/Arc/Circle/PolyLine/Spline). `colorOverridePenIndex` wird auf 0 gesetzt.
- `lineTypeName` ODER `lineTypeIndex` — Linientyp (nicht bei Hatch; dort ist es der Konturlinientyp).
- `drawIndex` — optional, 1..7 wie in Archicad.

Alles Nicht-Angegebene kommt aus `ACAPI_Element_GetDefaults` des jeweiligen Werkzeugs.

### 3.2 Geometrie

- Koordinaten in Metern, Projektnullpunkt, `{x, y}`.
- Winkel in Radiant (wie Lesebefehl).
- `arcs[]` = `{begIndex, endIndex, arcAngle}` mit 1-basierten Indizes wie beim Lesebefehl.
- PolyLine `closed:true` und Hatch: Schlusspunkt wird angehängt, falls er nicht schon gleich dem Startpunkt ist (Toleranz 0,1 mm). Liefert man einen Lesebefehl-Output mit Schlusspunkt zurück, entsteht kein doppelter Punkt.
- Spline `bezierDirs[]` = `{lenPrev, lenNext, dirAng}`, genau ein Eintrag je Punkt; fehlt das Feld, gilt `autoSmooth:true`.

### 3.3 Schraffur-Felder

- Füllung: `fillName` ODER `fillIndex`; fehlt beides → Werkzeug-Standard. Typ immer `API_FillHatch`.
- `foregroundPen`, `backgroundPen` (0 = transparent).
- `foregroundRGB`, `backgroundRGB` `{red, green, blue}` je 0–1 → setzt `APIHatch_HasFgRGBColor` / `APIHatch_HasBkgRGBColor` und `foregroundRGB` / `backgroundRGB`. Ohne Angabe werden diese Flags gelöscht, damit kein Default-Override durchrutscht.
- `contourPen` (0 = keine Kontur), `contourLineTypeName` ODER `contourLineTypeIndex`.
- `showArea` — Standard false.

## 4. Ablauf

1. **Prüfen**, ohne etwas anzulegen: Typ bekannt, Pflichtfelder da, Punktzahl ≥ Minimum, Radius > 0, `arcs`-Indizes im Bereich, `bezierDirs`-Länge = Punktzahl, Ebene/Füllung/Linientyp auflösbar, Geschoss existiert. Fehler je Element sammeln; fehlerhafte Elemente werden übersprungen, der Rest läuft.
2. **Anlegen** in EINEM `ACAPI_CallUndoableCommand ("ELM_SAB Create2DElements", …)`: je Element `ACAPI_Element_GetDefaults` → Felder setzen → `ACAPI_Element_Create`. Teamwork: neue Elemente gehören dem Anleger, keine Reservierung.
3. **Memos** (alle Handles nach Create per `ACAPI_DisposeElemMemoHdls` freigeben):
   - PolyLine/Hatch: `coords` 1-basiert, Größe `nCoords+1`, `pends[1] = nCoords`, `nSubPolys = 1`, `parcs` aus `arcs[]` (Vorlage: Tapir `AddPolyToMemo` in `ElementCreationCommands.cpp`).
   - Hatch: Polygon muss geschlossen sein (`coords[n] == coords[1]`).
   - **Spline: `coords` 0-basiert** (Header: „the coordinate with index 0 is also used"), erster und letzter Punkt verschieden; `bezierDirs` gleich lang; `autoSmooth`/`closed` im Element.
4. **Rücklesen** je angelegtem Element: `ACAPI_Element_Get` + Memo; Ebene, Geschoss, Typ und Koordinaten mit Sollwert vergleichen (Toleranz 0,1 mm). Hatch zusätzlich `ACAPI_Element_GetQuantities` (`API_HatchQuantity.surface`, `.perimeter`). Länge bei Line/Arc/Circle/PolyLine selbst aus der zurückgelesenen Geometrie berechnen (keine Mengenstruktur vorhanden). Spline: nur Punktabgleich.

## 5. Ausgabe

```json
{ "executionResults": [
  { "success": true, "elementId": {"guid": "…"}, "elementType": "Hatch",
    "floorIndex": 0, "layerIndex": 13, "layerName": "Z_FR_Rettungswege",
    "floorMatches": true, "layerMatches": true, "coordinatesMatch": true,
    "area": 1.0, "perimeter": 4.0,
    "fillIndex": 65, "fillName": "Vollfüllung" },
  { "success": false, "error": { "code": "APIERR_BADNAME (Zahlenwert aus Archicad)", "message": "Ebene 'Z_GIBTS_NICHT' nicht gefunden" } }
] }
```

- Reihenfolge = Eingabereihenfolge.
- `length` statt `area`/`perimeter` bei Line/Arc/Circle/PolyLine.
- Schema über `ELMResponseSchemaWithError`, Aufruffehler über `CreateErrorResponseELM`. Prüfung mit `~/.scratch/elmonkey/tools/elm_schema_scan.py`. Kein 4009.
- `success:true` nur, wenn Create NoError UND Rücklese alle `*Matches` true.

## 6. Nebenänderung

`Get2DGeometryOfElements` liest Splines bisher nicht (fällt in den ShapePrims-Fallback). Für den Rundweg
bekommt er einen `API_SplineID`-Zweig: `coordinates` (0-basiert gelesen), `bezierDirs`, `closed`, `autoSmooth`, `penIndex`, `ltypeIndex`.

## 7. Bauregeln

- Neue Dateien `Create2DElementsCommand.hpp/.cpp`, abgeleitet von `ELMCommandBase`, Registrierung in `AddOnMain.cpp`, `ELM_SAB_VERSION` → `0.9.26`, Menü-/Beschreibungstext.
- Kein C++20 (AC27/28 = C++17). Keine Text-Memos, also keine AC28-Memofalle.
- Vor dem Push das installierte 0.9.25-Bundle sichern; jeder Push überschreibt `ci-status` und das Release.
- Einbau nur bei null laufenden Archicad-Instanzen, danach `ELM_SAB.GetAddOnVersion` = 0.9.26.

## 8. Abnahme

Alles auf eigener Testebene `Z_KI_Test_2D`, Geschoss 0, außerhalb des Gebäudes.

1. **Schraffur zuerst** (Frist): Quadrat 1×1 m Vollfüllung grün per RGB → `area` 1,00, `perimeter` 4,00, `layerMatches`, `floorMatches`; Bildbeleg per `CaptureView`.
2. Je ein Element Line, Arc, Circle, PolyLine (mit Bogensegment, geschlossen), Spline (autoSmooth und mit bezierDirs) → Rücklese ok; Rundweg Spline über den erweiterten Lesebefehl.
3. Rundweg: Lesebefehl-Ausgabe einer vorhandenen Schraffur unverändert zurückgeben → Fläche gleich.
4. Fehlerfälle: Hatch mit 2 Punkten, unbekannte Ebene, Radius 0, `bezierDirs` falscher Länge, unbekannter `elementType` → je `{success:false, error}`, gültige Elemente im selben Aufruf werden trotzdem angelegt; fehlendes `elements` → lesbarer Aufruffehler.
5. Aufräumen: Testelemente löschen, Löschung rücklesen, Teamwork senden lassen, Testebene entfernen.
6. Doku: README-Tabelle, `recipes/fills-hatches.md` und `recipes/lines-polylines.md` mit Worked Example, `reference/mcp-extension.md` („Was der MCP NICHT kann" aktualisieren).
