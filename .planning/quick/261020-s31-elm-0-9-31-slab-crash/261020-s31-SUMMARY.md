# 261020-s31 — ELM_SAB 0.9.31: Absturz CreateSlabs mit Favoriten-Standards

Rückmeldung Maxl (15.10., BE-Plan 135054, AC29 5101): FATAL beim Anlegen von 3 Decken nach ApplyFavoritesToElementDefaults („Bodenabdeckung“). Stack CreateSlabsCommand::SetTypeSpecificParameters > BuildSlabMemoFromGeometry.

- Ursache: BuildSlabMemoFromGeometry prüfte nur memo.coords; Favoriten-Standards liefern coords ohne vertexIDs/edgeTrims/sideMaterials → BMReallocHandle auf Null-Handle. Zusätzlich memo für mehrere Decken wiederverwendet.
- Fix: jede Liste einzeln (fehlt → anlegen, sonst auf Sollgröße), Fehlermeldung statt Absturz bei Speicherfehler; vertexIDs mit sizeof(UInt32). Dach/Gelände hatten das sichere Muster schon.
- Check: Syntax mit Archicad-Vorab-Headern OK, kein C++20.
- Offen: CI, Live-Nachstellung (Favorit als Decken-Standard, 3 Decken in einem Aufruf, Testprojekt), weitere Fixes aus dem Team sammeln (Mudi), dann Merge + Einbau.

## Nachtrag 20.10. abends: Live-Test schlug fehl → zweiter Fix
- Live (leeres Projekt, Favorit „Bodenabdeckung“ als Standard, 3 Decken 5/15/8 Punkte): Archicad FATAL, Bericht Archicad-20261020(14-25-42)-[37204]-1-FATAL.rpt: „Fatal memory error in BMReallocPtr. Requested memory size is 136 bytes“ in BuildSlabMemoFromGeometry +0x340.
- Ursache: memo.sideMaterials aus den Favoriten-Standards ist kein vergrößerbarer BM-Block.
- Fix: sideMaterials immer frisch per BMAllocatePtr anlegen, alten Zeiger weder vergrößern noch freigeben (Herkunft unbekannt; AddPolyToMemo beschreibt jeden Eintrag neu).
